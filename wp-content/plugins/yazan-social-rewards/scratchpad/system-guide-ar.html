1. نظرة عامة

يزن للمكافآت الاجتماعية والسفراء منصّةٌ متكاملة للولاء والمكافآت والتفاعل الاجتماعي، مبنيّة على ووردبريس وووكومرس، ومصمّمة خصّيصاً لمتجر يزن الفاخر (خواتم العقيق اليمني والفضّة).

تعمل المنصّة كإضافة (Plugin) مستقلّة تماماً: لا تُعدِّل نواة ووردبريس ولا ووكومرس ولا القالب ولا أي إضافة أخرى — كل التكامل يجري عبر الخطاطيف (hooks) والفلاتر، ممّا يجعلها آمنة عند التحديثات وقابلة للنقل.

تغطّي المنصّة رحلة الولاء كاملةً: كسب النقاط من الشراء والتفاعل، وتحويلها إلى رصيد متجرٍ أو مكافآت، وبناء برنامج سفراء وإحالات، وإطلاق حملاتٍ تسويقية، وتصعيد العملاء عبر مستويات ولاء، ومراقبة الأداء بالتحليلات، والتواصل مع العملاء عبر إشعاراتٍ متعدّدة القنوات — مع واجهة برمجية عامة وخطاطيف مطوّرين تفتح النظام للإضافات الخارجية.

مبادئ التصميم

  • مستقلّ ومعياري: 14 محرّكاً منفصلاً، كلٌّ يمكن تعطيله وحده عبر عَلَم ميزة.
  • مفصول بالأحداث: المحرّكات لا تتخاطب مباشرةً بل عبر ناقل أحداثٍ ومجالاتٍ مشتركة.
  • آمن ماليّاً: الدفاتر تراكميّة (إضافة فقط)، والعمليات معامَلاتيّة مع تعويضٍ عند الفشل.
  • قابل للتوسّع: إضافة محرّك أو موصّل أو نوع مكافأة أو حدث دون لمس النواة.

2. المعمارية والنواة

النظام مبنيّ ببرمجة كائنية حديثة بمسارات PSR-4 (النطاق Yazan\Rewards يقابل مجلّد src/)، مع مُحمِّلٍ ذاتيّ لا يحتاج أدواتِ بناء. يقوم على مكوّناتٍ أساسية:

المكوّنالوظيفة بالتفصيل
المُنسّق Pluginنقطة الدخول: يبني الحاوية، يحمّل المحرّكات، ويشغّلها عبر register() ثم boot().
حاوية الحقن Containerحقن التبعيات: تبني الخدمات كمفردات (singletons) وتشاركها بين المحرّكات.
سجلّ الوحداتيرتّب المحرّكات طوبولوجيّاً حسب تبعيّاتها المعلَنة قبل تشغيلها.
ناقل الأحداث EventBusالناقل الداخلي: dispatch() يوزّع الحدث على المشتركين وعلى خطّاف ووردبريس، فتتفاعل المحرّكات دون معرفة بعضها.
مُحمِّل الخطاطيفيربط الكائنات التصريحية بخطاطيف add_action / add_filter.
الإعدادات Settingsقارئ إعداداتٍ مُنمَّط فوق خيارٍ واحد مدموج مع الافتراضات، بمسارات نقطيّة وأعلام ميزات.
المُجدوِل Schedulerغلافٌ حول Action Scheduler للمهام الدورية والمُؤجَّلة والدُّفعات غير المتزامنة.
المستودعاتأساس الوصول للجداول الـ23؛ اسم الجدول = بادئة الموقع + yazan_rw_ + الاسم.
الأمانالصلاحيات والنونس وتحديد المعدّل — أساس حماية كل عملية.

الوحدة (Module) تُنفّذ واجهة ModuleInterface بدوالّ id / dependencies / register / boot / activate / deactivate، وتُضيف schema() إن ملكت جداول. تُنشأ الوحدات دون وسائط، وتأتي تبعيّاتها من الحاوية.

4. محرّك القواعد

القلب الذي يقود اكتساب النقاط: يُبنى كل شيء بلا كود على صيغة حدث ← شروط ← إجراءات، وتُدار القواعد من لوحة الإدارة. عند وقوع حدثٍ يُبنى «سياق» بالحقائق، ثم تُطابَق الشروط، فتُنفَّذ الإجراءات.

الأحداث

إتمام طلب، أول عملية شراء، شراء منتج/فئة، بلوغ مبلغ طلب، إنشاء حساب، عيد ميلاد، تسجيل دخول، إكمال ملف، مراجعة، إتمام إحالة، إرسال صورة/فيديو.

الشروط

مستوى العميل، النقاط مدى الحياة، سجلّ الشراء، منتج/فئة معيّنة، تاريخ/نافذة زمنية، دور المستخدم — تُطابَق عبر قائمة سماحٍ صارمة.

الإجراءات

إضافة/خصم نقاط، ترقية المستوى، منح وسام، إنشاء قسيمة، إرسال إشعار — وكلٌّ منها يُنسَّق عبر المحرّكات القائمة. ويمنع النظام التكرار عبر مفاتيح تنفيذٍ لكل طلب/مستخدم.

5. النقاط والمحفظة

دفتر النقاط

دفترٌ ماليّ تراكمي (إضافة فقط): كل صفٍّ يسجّل المستخدم والنقاط (بإشارة) والرصيد قبل/بعد والسبب والمصدر والحالة. الرصيد = مجموع الصفوف المعتمَدة — تصميمٌ آمنٌ ضدّ تسابق العمليات ويحفظ سجلّاً محاسبيّاً كاملاً (النقاط التزامٌ ماليّ). يُخزَّن الرصيد المشتقّ في بيانات المستخدم لقراءةٍ فوريّة.

الكسب: نقاطٌ لكل وحدة عملةٍ من الطلب، ومكافآت تسجيلٍ ومراجعةٍ وعيد ميلاد. وتتراكم المُضاعِفات (مستوى الولاء، الحملة) على مقدار الكسب. الحالة: النقاط تُعتمَد عند الكسب، مع طابور مراجعةٍ للمعلّقة. الانتهاء (اختياري): عند تفعيله تُختَم النقاط بتاريخ انتهاءٍ، وتوجد مهمّة تُنهي المنتهية ومهمّة تذكيرٍ مسبق قبل الانتهاء.

محفظة رصيد المتجر

رصيد متجرٍ نقديّ يُكتسَب من المكافآت أو العمولات ويُطبَّق خصماً عند الدفع (كرسمٍ سالب في سلّة ووكومرس). قابل للضبط: نسبة تحويل النقاط إلى رصيد، الحدّ الأدنى للاستبدال، والنسبة القصوى من قيمة السلّة القابلة للدفع بالرصيد.

6. المكافآت والاستبدال

كتالوجٌ يُدار بلا كود؛ لكل مكافأةٍ تكلفة نقاطٍ ونافذة توفّرٍ ومخزونٌ وحدٌّ لكل مستخدم.

أنواع المكافآت

رصيد (محفظة)، قسيمة ووكومرس، شحن مجاني، منتج مجاني، وأربع مكافآت خدمة (خدمة VIP، تنظيف الخاتم، تلميع الخاتم، منتج حصري) تُنفَّذ عبر قسيمةٍ وطابور خدمةٍ للطاقم.

مسار الاستبدال (معامَلاتي)

تحديد المعدّل ← التحقّق من التوفّر والحدود والرصيد ← حجز المخزون ← خصم النقاط ← تسليم القيمة عبر مُصدِر المكافأة المناسب ← التسجيل ← إعلان الحدث. وإذا فشل التسليم بعد الخصم تُعاد النقاط تلقائيّاً ويُحرَّر المخزون (معاملة تعويضيّة) — فلا يخسر العميل نقاطه أبداً. والنوع غير المدعوم يُرفَض قبل أي خصم.

قابلية التوسّع

التسليم يمرّ عبر سجلّ مُصدِري المكافآت (نوع ← مُصدِر)؛ ويمكن لطرفٍ ثالث تسجيل نوع مكافأةٍ جديد بتسليمٍ مخصّص عبر yazan_register_reward_provider().

7. الإحالة والسفراء

الإحالة

رمزٌ ورابطٌ فريدان لكل عميل، وتتبّعٌ دقيق لمن أحال مَن، وشجرة إحالةٍ من مستويين (المُحيل المباشر + مُحيله). وقواعد المكافأة قابلة للضبط لكل مستفيد (نقاط أو رصيد، مبلغ ثابت أو نسبة) وتُدفَع عند أول طلبٍ للمُحال. ويتتبّع النظام قيمة الشراء والإيراد والنقاط لكل إحالة.

منع التلاعب: يكشف إحالة الذات (المباشرة والمقنّعة عبر تطابق بريدٍ مُطبَّع)، وتجميع عنوان IP المرتبط بالمُحيل، ويحجز الإحالة المشبوهة للمراجعة بدل صرفها.

السفراء

نظام طلباتٍ (تقديم ← اعتماد)، وعمولةٌ بنسبةٍ مئوية على الطلبات المنسوبة تُدفَع رصيدَ متجرٍ في النسخة الأولى (مع واجهةٍ محجوزة لمدفوعاتٍ نقديّة لاحقاً)، ولوحةٌ للسفير في «حسابي» تعرض المستوى والترتيب والتقدّم والإحصاءات والإحالات.

8. الحملات

نوعان مكمّلان:

  • حملات مضاعفة الكسب: تزيد النقاط المكتسبة بمُعامِلٍ خلال فترةٍ محدّدة.
  • حملات تسويقية / محتوى المستخدم: بمهامّ ومكافآتٍ وجمهورٍ مستهدف.

دورة الحياة

الحالات: مسودّة ← مجدولة ← نشطة ← متوقّفة/مكتملة ← مؤرشفة، بانتقالاتٍ مُتحقَّق منها. ومهمّةٌ يوميّة تُفعّل الحملات المجدولة وتُكمل المنتهية تلقائيّاً حسب تواريخ البدء/الانتهاء.

الاستهداف والمشاركة

الجمهور: الكل / مستوى / دور / مستخدمون محدّدون. ينضمّ العميل ويرسل محتوى المهمّة (رابطاً)، فتُراجَع الإرسالات وتُمنَح نقاط المهمّة ومكافأة الإكمال عند اعتماد كل المهامّ المطلوبة. ولكل حملةٍ تحليلات (المشاركون، الإرسالات، المعتمَد/المرفوض، النقاط، معدّل التفاعل).

9. الإنجازات ومستويات الولاء

الإنجازات أوسمةٌ تُفتَح عند بلوغ معايير محدّدة، وتُعرَض في لوحة العميل.

مستويات العضوية

أربعة مستويات — برونزي / فضّي / ذهبي / بلاتيني — لكلٍّ عتبةُ نقاطٍ ومُضاعِفُ كسبٍ ونسبةُ خصمٍ عند الدفع وشارةٌ ولون. والقاعدة الصارمة: المستوى يُحدَّد بالنقاط المكتسبة مدى الحياة، لا الرصيد الحالي، فلا ينخفض العميل عند الاستبدال. وتُحسَب الترقية والخصم مباشرةً من جدول المستويات لضمان تطابق ما يُعرَض مع ما يُطبَّق فعلاً عند الدفع.

10. موصّلات التواصل الاجتماعي

إطارٌ غير مُثبَّت برمجيّاً: تأتي الشبكات من إعدادٍ قابلٍ للتوسّع (إنستغرام، تيك توك، فيسبوك، يوتيوب، بنترست، سناب شات، لينكدإن)، وكلٌّ يدعم OAuth وربط الحساب والتحقّق.

طريقتا التحقّق

عبر واجهة المنصّة (API): عند توفّر مفاتيح التطبيق وربط العميل حسابه. الإرسال اليدوي: يرسل العميل رابط المنشور، فيفحص النظام ستّ فحوص: وجود الرابط، ملكيّة الحساب، الوسم المطلوب، الإشارة/الرابط المطلوب، صحّة التاريخ ضمن النافذة، وعدم التكرار. يُعتمَد تلقائيّاً عند اجتياز كل الفحوص المطلوبة، وإلا يُحال للمراجعة.

الأمان

مفاتيح التطبيق تُخزَّن للكتابة فقط (تُعرَض آخر 4 أرقام)، ورموز OAuth للعملاء مُشفَّرة عند التخزين، والجلب اليدوي محميٌّ ضدّ هجمات SSRF (يمنع العناوين الداخليّة).

11. مكافحة الاحتيال

محرّك مخاطر يفحص كل إجراءٍ مُكسِب عبر كواشف قابلة للتركيب، ويعطي قراراً (سماح/مراجعة) بناءً على درجةٍ مرجَّحة.

الكواشف والحالات

الكواشف: محتوى/روابط مكرّرة، حسابات متعدّدة (بصمات بريد/IP مشتركة)، تفاعل مصطنع، وسرعةٌ غير طبيعيّة. الحالات: معتمَد / مرفوض / مشبوه / مراجعة يدوية.

الإنفاذ

عند الاشتباه تُحجَز المكافأة (لا يُدفَع شيء) بانتظار مراجعة الإدارة. والاعتماد يُطلِق المكافأة مرّةً واحدة؛ والرفض يسترجع المكافأة المدفوعة (خصم النقاط/الرصيد) ويُعلِّم الحساب. مع تحديدٍ للمعدّل وسجلّاتِ احتيالٍ وأدواتِ مراجعة، ومطابقةٍ بين طابور الاحتيال وحالة الإرسال الاجتماعي لسدّ أي تسرّب.

12. التحليلات

لوحةٌ للقراءة فقط (بصلاحية) تجمع مؤشّرات الأداء في ثلاث مجموعات:

  • العملاء: الإجمالي، عملاء VIP (أعلى مستويات)، السفراء النشطون، توزيع المستويات.
  • الحملات: الأفضل أداءً، المشاركة، المحتوى المُولَّد، معدّل التفاعل.
  • الأعمال: معدّل الاحتفاظ، إيرادات الإحالة، القيمة الدائمة CLV، تكلفة المكافآت، والتزام النقاط (قيمةً).

تشمل رسوماً بيانية SVG مضمّنة (خطّي، أعمدة، دائري) وجداولَ وتصدير CSV. وهي مُحسَّنة الأداء: تُخزَّن كامل النتائج مؤقّتاً لكل نطاقٍ زمني، مع قراءةٍ مُجمّعة من جدول الطلبات (HPOS) للاحتفاظ وCLV.

13. الإشعارات

تحوّل الأحداث المهمّة إلى إشعاراتٍ تُوزَّع عبر القنوات مع احترام تفضيلات العميل.

الأحداث المُشعَرة

نقاط مكتسبة، نقاط مستبدَلة، حملة جديدة، حملة تنتهي، ترقية مستوى، إنجاز مفتوح، انتهاء صلاحية نقاط (وتذكيرٌ مسبق)، طلب/إتمام خدمة، إحالة/عمولة، مراجعة حملة.

القنوات

بريد HTML بعلامة يزن (RTL + نسخة نصّية، ولا يمسّ بريد ووكومرس)، داخل الموقع (صندوق وارد)، وWebhook موقَّع بـ HMAC لأنظمة الأتمتة. وقنوات SMS / Push / WhatsApp مُوصّلة لكن خاملة حتى يُسجَّل مزوّد.

التفضيلات والملخّص

فئاتٌ (خدمة، استبدال، نقاط، إحالة، مستوى، إنجاز، حملة، نظام)؛ الفئتان المعامَلاتيّتان (الخدمة والاستبدال) تُرسَلان دائماً، والباقي يتحكّم بها العميل (بريد: فوري/ملخّص يومي/إيقاف؛ داخل الموقع: تشغيل/إيقاف). وفئة «النقاط» تبدأ على الملخّص اليومي لتفادي الإزعاج، ويجمع الملخّص الإشعارات غير العاجلة في رسالةٍ واحدة. والبثّ (حملة جديدة/تنتهي) يُوزَّع على دفعاتٍ غير متزامنة.

14. قاعدة البيانات

ثلاثةٌ وعشرون جدولاً مخصّصاً بادئتها wp_yazan_rw_، يُنشئها ويُرقّيها مُثبِّتٌ واحد عبر dbDelta (إضافةً فقط، دون فقدان بيانات). الدفاتر المالية تراكميّة، والأرصدة مُخزّنة في بيانات المستخدم؛ والأموال بنوع DECIMAL(19,4) والنقاط BIGINT، وكل جدولٍ يحمل فهارسه.

17. واجهات الإدارة والعميل

لوحة الإدارة

قائمة Yazan Rewards (بصلاحية manage_yazan_rewards): القواعد، المكافآت، النقاط، طابور الخدمة، الحملات، التواصل، الاحتيال، التحليلات، الإشعارات — وكلٌّ شاشةُ إدارةٍ تعمل عبر REST.

حساب العميل

مركز المكافآت (/my-account/rewards/): الرصيد، رصيد المتجر، الكتالوج، الحملات النشطة، النشاط الأخير، ولوحة إشعاراتٍ (صندوق وارد + تفضيلات). ولوحة العضوية/السفير: شارة المستوى، الترتيب، التقدّم للمستوى التالي، الحملات، الإنجازات، إحصاءات الإحالة.

18. الأمان والتدقيق

اجتاز النظام تدقيقاً إنتاجيّاً (الإصدار 1.11.1) بنتيجة «جاهز للإنتاج»:

  • لا حقن SQL: كل الاستعلامات مُجهَّزة (prepare)، وأسماء الجداول ثابتة لا من مدخلات المستخدم.
  • الصلاحيات والنونس: كل مسار إدارةٍ يتطلّب صلاحية، والعميل يرى بياناته فقط (لا IDOR)، وحماية CSRF عبر رمز wp_rest.
  • المدخلات والمخرجات: تنقيةٌ على الدخل وتهريبٌ على الخرج في كل قالبٍ ولوحة.
  • الأسرار: للكتابة فقط، والرموز مُشفَّرة، ولا أسرار مضمّنة في الكود.
  • التوافق: PHP 8.1/8.2 وووردبريس 6.5 وووكومرس/HPOS — نظيف.

والدفاتر لا تُحذَف عند إلغاء التفعيل، والبيانات محفوظة افتراضيّاً عند الإزالة (الحذف اختياريّ صريح).

19. التثبيت

المتطلبات: ووردبريس 6.5+، ووكومرس 8.0+ (يوفّر Action Scheduler)، PHP 8.1+ مع امتداد sodium، ويُفضَّل HTTPS.

الخطوات: نسخ الإضافة إلى wp-content/plugins/ وتفعيلها (بعد ووكومرس)، ثم Settings → Permalinks → حفظ مرّة لتسجيل نقاط «حسابي». وعند التفعيل: تُنشأ 23 جدولاً، وتُمنَح صلاحيتان (manage / view_yazan_rewards) للمدير ومدير المتجر، وتُزرَع الافتراضات (المستويات…)، وتُجدوَل المهام الدورية. ويُنصَح بتعريف YZRW_TOKEN_KEY في wp-config.php لتشفير الرموز.

20. النسخ الاحتياطي والترقية

النسخ الاحتياطي

انسخ جداول wp_yazan_rw_* (خاصّةً الدفاتر المالية) والخيارات (بما فيها الأسرار وعلامات الإصدار) وبيانات المستخدم _yzrw_* ضمن نسخك المعتادة. ولا توجد واجهة نسخٍ داخل هذه الإضافة (تتوفّر في إضافة yazan-core المنفصلة)، لكن بياناتها مشمولةٌ في أي نسخةٍ كاملة لقاعدة البيانات.

الترقية والتراجع

تُطبَّق الترقية تلقائيّاً عبر «المُرحِّل» عند تغيّر الإصدار: تشغيل dbDelta الإضافيّ + إعادة تشغيل تفعيل كل وحدةٍ + تحديث الروابط — دون إعادة تفعيلٍ يدوية. والتراجع آمنٌ لأن التغييرات إضافيّة (الأعمدة الجديدة تُهمَل من الكود الأقدم). قاعدة ذهبية: المهام الدورية تُجدوِل نفسها على خطّاف init لا في boot() (لأن مُجدوِل الإجراءات لا يكون جاهزاً باكراً).
